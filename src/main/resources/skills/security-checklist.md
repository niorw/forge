# 安全审查清单

## 审查态度
宁可误报也不要漏报。安全问题的代价远大于功能问题。

## 维度一：SQL 注入风险
- [ ] 所有 SQL 是否使用参数化查询（PreparedStatement / MyBatis #{}）
- [ ] 是否存在字符串拼接 SQL（\${} 或 String.format 拼接）
- [ ] 动态 ORDER BY / LIMIT 是否有白名单校验
- [ ] LIKE 查询是否转义了通配符

## 维度二：越权访问风险
- [ ] 接口是否有权限校验（@RequiresPermissions / 自定义注解）
- [ ] 是否有水平越权风险（用户 A 能操作用户 B 的数据）
- [ ] 是否有垂直越权风险（低权限用户访问高权限接口）
- [ ] 内部接口是否有鉴权（不能只靠 URL 隐藏）

## 维度三：敏感信息泄露
- [ ] 日志中是否打印了身份证、银行卡、手机号等敏感字段
- [ ] 返回值中是否暴露了内部 ID 或系统路径
- [ ] 异常信息中是否包含了堆栈或 SQL 语句
- [ ] 配置文件中是否有明文密码

## 维度四：超时熔断保护
- [ ] 外部服务调用是否设置了超时时间
- [ ] 是否有熔断降级策略（Sentinel / Resilience4j）
- [ ] 数据库连接池是否配置了最大等待时间
- [ ] 线程池是否配置了拒绝策略

## 维度五：输入校验
- [ ] 接口入参是否有 @Valid / @NotNull / @Size 等校验注解
- [ ] 金额/数量字段是否有范围校验（不能为负数）
- [ ] 字符串字段是否有长度限制
- [ ] 枚举字段是否有合法值校验

## 维度六：并发安全
- [ ] 是否有竞态条件（check-then-act）
- [ ] 金额操作是否使用了乐观锁或分布式锁
- [ ] 幂等性是否保证（重复请求不会重复扣款）
- [ ] 状态机转换是否有并发保护

## VERDICT 输出格式
最后一行必须是：VERDICT: PASS 或 VERDICT: FAIL
